# PDP-008: shipping domain model

Internal planning file, excluded from the site. Revised 2026-11-03. It mirrors the series
standard, the Notion page "Shipping Domain Model & Per-Chapter Examples", which the Java and C#
books also use. An earlier version of this file was reconstructed without the standard and has
been replaced. The spike-derived notes (see spikes.md) are kept and re-expressed in the standard
names. Examples are written fresh in idiomatic Python 3.15 (`Protocol`, frozen slotted
dataclasses, plain callables, generators, `functools.singledispatch`, `match`); no C#-only or
Java-only feature is used and nothing is ported from the sibling books.

## Seven domain areas (standard names)

| Area | Entities | Mostly serves | Python notes |
| --- | --- | --- | --- |
| Consignment | Consignment, Container, Commodity, Weight, Dimensions | creational, structural, value types | `Consignment` is a frozen slotted dataclass; amendments through `dataclasses.replace`. `ConsignmentId` is a `NewType` over `str`. `Weight` already exists from the prerequisites example. `Commodity` and `Container` kinds are frozen dataclasses or enums, per chapter. |
| Carrier | Carrier, CarrierGateway, carrier SDK types | Adapter, Factory, Proxy, DI | `CarrierGateway` is a `Protocol` (`book`, `track`, `cancel`). Fictional carrier codes `FASTLINE` and `AIRCO` only, never real brands; adapters `FastlineGateway`, `AircoGateway`. The carrier SDK types are small stand-in classes with different shapes. `CarrierQuote` is the carrier's answer. `CarrierTimeoutError` (ruff N818 wants the `Error` suffix). |
| Rating | RateQuote, Tariff, Surcharge, Discount, Money | Strategy, Decorator, Interpreter | `Money` is a frozen dataclass over `Decimal` with a currency; adding different currencies raises. `RateQuote` is the result. `Tariff` maps zone and weight band to `Money`; `TariffTable` is the loaded table. Supporting names: `RateRequest`, `RateEngine`, `RateCalculator`, `PricingRule` (callable type alias), `RatingError`. |
| Routing | Sailing, Vessel, PortCall, StowagePlan, SlotId | Composite, Iterator, concurrency | `SlotId` is a frozen dataclass value type. Port codes are UN/LOCODE strings (`RTM`, `SGSIN`). `StowagePlan` reserves one `SlotId` per `Sailing`; the reservation is the shared state in the concurrency chapters. |
| Tracking | HandlingEvent, TrackingHistory, ConsignmentStatus | Observer, State, async streams | `HandlingEvent` is a frozen dataclass family under `type HandlingEvent = Booked \| Loaded \| Departed \| Cleared \| Delivered` where dispatch or `match` needs classes, or one class with a `HandlingKind` enum where a single class fits; pick per chapter and say which. `ConsignmentStatus` is an enum. `TrackingHistory` is iterable and lazily paged. |
| Documentation | CustomsDeclaration, BillOfLading, Manifest | Chain of Responsibility, Template Method, context managers | `ManifestWriter` is a context manager over a file handle. `ClearanceStage` is a callable in a chain. Documents are frozen dataclasses with a `DocumentKind` enum for dispatch tables. |
| Billing | Invoice, LineItem, Settlement | Builder, Memento, final project | `Invoice` is built from `LineItem`s; `Settlement` closes it. Money arithmetic reuses `Money`. |

Series supporting names (reuse where they fit, in Python spelling): `RateRequest`, `RateEngine`,
`TariffTable`, `BookingRequest`, `ConsignmentId`, `ConsignmentStatus`, `HandlingKind`, `LineItem`,
`CustomsDeclaration`, `ManifestWriter`, `ClearanceStage`, `CarrierQuote`.

## Rules

- Never invent a new domain area. If a pattern seems not to fit, the framing is wrong; reframe it
  inside one of the seven areas.
- Examples may reuse entities from earlier chapters. The tariff table recurs; the rate engine
  recurs across SOLID, anti-patterns and the legacy part. Reuse is the point.
- No UI, no container, no service boundary.
- Each example lives at `examples/NN-slug/` with a README carrying behavioural verification.
- Fictional carrier codes `FASTLINE` and `AIRCO` only; port codes are UN/LOCODEs such as `RTM`
  and `SGSIN`.
- Use `X | None`, never `Optional`.
- Type aliases are named for the role (`PricingRule`, `Layer`), consistent with the naming chapter
  that argues for role plus mechanism names.
- The book's own idiomatic-Python chapters (decorators done right, descriptors, singledispatch,
  metaclasses and `__init_subclass__`, `__getattr__`) also draw from the seven areas.

## Non-overlap rules

- **ch20 vs ch26**: ch20 is the GoF Decorator as runtime object wrapping on the `RateCalculator`
  Protocol (`Discount`, `Surcharge`, `Tax` over `Money`), contrasted with `@retry` / `@audited(sink)`
  on `quote_carrier()`. The overlap case (a decorator function that returns a wrapper object)
  gets one paragraph in ch20, not a section; the syntax-specific teaching (`functools.wraps`,
  `ParamSpec`) stays in ch26, and so do stacking order for caches and the reconciliation row on a `wraps`-less wrapper (r09 decision 5). ch20 keeps one syntax stacking-order witness only, `@audited` over `@retry` against the reverse, because that order is fixed at definition time. ch26 uses only Documentation renderers or `LineItem` formatting
  (`@timed_render`, `@cached_for`, a class decorator for `DocumentKind`) and never touches
  `RateCalculator`.
- **ch25 vs ch28**: ch25 shows Visitor via singledispatch as one of three mechanisms over
  `HandlingEvent` or `Commodity` kinds (no double dispatch; closed hierarchies prefer union +
  `match` + `assert_never`). ch28 teaches singledispatch in depth on `Commodity` kinds and
  `Container` kinds via `singledispatchmethod` (registration, forward-reference, mypy and
  global-state caveats); no `HandlingEvent` visitor there.
- **ch9 vs ch11**: ch9 owns the Protocol facts (positional-only `/`, inferred variance,
  `runtime_checkable` is presence-only) and leaves the mock caveat to the ISP/DIP chapter; ch11 gives the
  double matrix (mock classes are assignable to every type) and the reason to use `create_autospec`.
- **ch24 vs ch38**: ch24 keeps sync generators; one pointer to asyncio and the patterns, by title; the `aclosing` finding is taught there.
- **ch18 vs ch37**: ch18 owns `functools.cache` not being call-once under threads on the
  `Tariff` table; ch37 only refers back to it when discussing the GIL.
- **ch20 vs ch30**: ch20 Proxy is the caching proxy over `CarrierGateway`
  (`CarrierGatewayProxy`). ch30 is a lazy `TrackingHistory` loader using `__getattr__`; no
  gateway there.
